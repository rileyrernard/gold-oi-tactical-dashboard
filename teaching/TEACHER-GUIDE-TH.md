# บทผู้สอน 60 นาที

Armriley · ใช้กับ Canva 28 หน้า · แนวการสอน: คำถาม → สมมติฐาน → ข้อมูล → ตรวจความสัมพันธ์ → เปรียบเทียบ → ข้อสรุป

เนื้อหานี้เป็นคำพูดประกอบ ไม่ต้องอ่านทุกประโยคเหมือนสคริปต์ ใช้ภาษาที่ผู้เรียนเข้าใจ ทุกตัวเลขในแบบฝึกเป็น DEMO หากแสดงข้อมูลจริงต้องระบุวัน contract/expiry และที่มาของรอบนั้นใหม่

## นาที 0–10: พื้นฐาน (หน้า 1–8)

**1 ปก:** “วันนี้เราไม่ได้ฝึกเดาราคาให้ถูกทุกครั้ง เราฝึกแยกก่อนว่าเลขตรงหน้าบอกอะไร และมีส่วนไหนที่เรากำลังเติมเรื่องราวเข้าไปเอง สุดท้ายเราจะใช้เครื่องมือช่วยคำนวณ แต่ยังตรวจเหตุผลได้ด้วยตัวเอง”

**2 แผนเรียน:** เก็บช่วงลงมือท้ายคาบไว้จริง ถ้าการติดตั้งนานให้ใช้ DEMO ที่เตรียมแล้วสาธิต และให้คู่มือติดตั้งกลับไป ไม่แกล้งข้ามขั้นแล้วบอกว่าทุกเครื่อง live พร้อม

**3 Futures/Options:** “Futures หนึ่งสัญญามีคนรับฝั่ง long และ short ส่วน options เราเริ่มจากสิทธิของ buyer กับภาระ writer บน underlying อย่าเพิ่งท่อง Call คือขึ้น Put คือลง เพราะถือคนละฝั่งหรือถือเป็น spread ได้” ชี้แยก underlying, strike, expiry ให้ผู้เรียนพูดกลับ

**4 OI:** “หนึ่งคู่ long-short นับหนึ่ง ไม่ใช่สอง และจำนวนนี้ไม่ใช่ดอลลาร์สุทธิ เรารู้ว่ามีสัญญาค้างเท่าไร แต่ยังไม่รู้ว่าใครถือเพื่ออะไร” อ้างนิยาม CME About Volume ใน SOURCES

**5 Volume/ΔOI:** “Volume ถามว่าวันนี้ซื้อขายไปเท่าไร OI ถามว่าจบแล้วค้างเท่าไร ΔOI ถามว่าค้างเปลี่ยนจากวันฐานเท่าไร” ให้ผู้เรียนแยก stock กับ flow โดยไม่ใช้ศัพท์ยาก ต้องตรง contract และช่วงเวลา

**6 กลไกเปิด/ปิด:** เดินตารางทีละแถว จับคู่หนึ่งสัญญาทั้งสามแบบ “Volumeเพิ่มได้ทุกแถว แต่ OI มีเพิ่ม ลด หรือไม่เปลี่ยน จึงใช้ Volume แยกการเปิด/ปิดไม่ได้” ย้ำโจทย์สมมติ

**7 อ่านได้/ไม่ได้:** ให้ผู้เรียนเลือกข้อความที่หลักฐานรองรับ เช่น concentration กับข้ออ้างว่า dealer short gamma อันหลังต้องมีข้อมูลเพิ่ม อย่าตอบแค่ว่า OI มีประโยชน์โดยไม่ระบุขอบเขต

**8 ก่อนตีความ:** ทำ checklist contract/expiry/date/timezone/units/basis ถ้าผู้เรียนมีกราฟ CFD ให้ชี้ว่ามันอาจไม่ใช่ futures เดือนเดียวกับ options ไม่เปลี่ยนกราฟของเขาเอง

## นาที 10–25: Matrix และข้อจำกัด (หน้า 9–15)

**9 Matrix 4 ช่อง:** บอกว่าเป็นกรอบตั้งสมมติฐาน futures ที่จับคู่ช่วงเดียวกัน ก่อนเรียก long/short ให้พูดประโยคสังเกตก่อน เช่น “ราคาขึ้นและจำนวนคู่สัญญาค้างเพิ่ม” นี่ตรวจได้ ส่วน long build-up คือภาษาตีความ ไม่ใช่ long มีจำนวนมากกว่า short

**10 ราคาเพิ่ม/OIเพิ่ม:** “เราสงสัยว่ามีการก่อสถานะใหม่ระหว่างราคายอมรับสูงขึ้น แต่ short ก็เปิดเป็นคู่ด้วยเสมอ เราจะดูต่อว่าราคาถือเหนือระดับได้ไหมและ Volume เทียบฐานอย่างไร” หลีกเลี่ยงคำว่า smart money หรือ whale

**11 ราคาลด/OIเพิ่ม:** ใช้หลักเดียวกัน “สถานะใหม่ก่อพร้อมราคาลง เป็น short build-up hypothesis แต่เราไม่ได้เห็นว่าใครเป็นผู้เริ่มหรือ hedge อะไร” ถ้าเป็น Call/Put OI จะไม่ใช้ cell นี้แทน futures

**12 ราคาเพิ่ม/OIลด:** “สอดคล้อง covering แต่การปิดสุทธิตอนสิ้นวันไม่บอกว่ามีการบังคับซื้อเมื่อไหร่ ถ้าจะเรียก squeeze ต้องอธิบายหลักฐานเพิ่ม เช่น การเร่งตัวผ่านจุดเสี่ยงของตำแหน่ง ไม่ใช่เห็นแท่งเขียวกับ OI ลดแล้วจบ”

**13 ราคาลด/OIลด:** “สอดคล้อง liquidation แต่คำว่า forced ต้องมีหลักฐานอีกชั้น คนอาจลดความเสี่ยงเอง ปิดหมดอายุ หรือย้ายเดือนก็ได้” ถามให้ผู้เรียนบอกสิ่งที่ข้อมูล EOD ยังขาด

**14 Volume:** ตั้ง baseline ก่อนมองผล ห้ามตั้งสูง/ต่ำย้อนหลังให้เข้ากับเรื่องเล่า “มากกว่าปกติของสัญญานี้ในเวลาแบบเดียวกัน” ต่างจาก “มากกว่าตัวเลขที่เราเลือกเอง” ใช้เป็น participation ไม่ใช่เลือก bullish/bearish

**15 หลักฐานกับสมมติฐาน:** ให้จับคู่สี่คำ accumulation/squeeze/covering/liquidation กับข้อจำกัด การสะสมในกรอบไม่ได้ยืนยันว่ากำลังสะสม long เป้าหมายคือรู้ว่าสถานการณ์ใดสอดคล้องและยังขาดอะไร ไม่ใช่บังคับตั้งชื่อทุกกราฟ

## นาที 25–35: Options กับ Dashboard (หน้า 16–20)

**16 Options:** “ตอนนี้เราเปลี่ยนชุดข้อมูลมาเป็น options แล้ว ต้องเปลี่ยนวิธีพูดด้วย Strikeคือราคาตามสัญญา ไม่ใช่ราคาเข้าบัญชี broker ที่แปลงเสร็จ Call/Put concentration เป็นจุดให้ตรวจ ไม่ใช่ผนังที่ราคาห้ามผ่าน”

**17 ข้อผิดพลาด:** ให้ผู้เรียนแก้ข้อความเอง ประโยค “Volumeมากเท่ากับเปิดใหม่” แก้เป็น “มีการซื้อขายมาก แต่ไม่รู้ opening/closing” ส่วน “OIลดเท่ากับหมดความสนใจ” ต้องพิจารณา roll/expiry และสัญญาถัดไป

**18 Dashboard:** ใช้ `runs/demo/dashboard.html` ที่มีป้าย DEMO จริง เปิดบน browser ชี้วันที่/KPI/Top15/explorer/history/levelmap อย่าเปลี่ยนตัวเลขในภาพให้ดูเหมือนตลาดปัจจุบัน

**19 Top15:** คลิกบวกและลบคนละฝั่ง “อันดับคือขนาดการเปลี่ยน ไม่ใช่อันดับความแม่น” สีหมายถึงจำนวนสัญญาเพิ่ม/ลด Prior OI ที่ derive ต้องยังติดป้ายคำนวณ เปรียบเทียบข้อมูลวันฐานจริงเมื่อมี ขยับตัวกรองแล้วชี้ว่าอันดับกับ KPI คงเดิม

**20 Views:** Positioning ตอบว่าภาวะคืออะไรและอะไรเปลี่ยนมุมมอง Swing ตอบว่าต้องเห็น trigger/confirmation/invalidation แบบไหน ทุก scenario อาจไม่เกิด และไม่ใส่ sizing/leverage ให้บุคคลโดยไม่มีโจทย์แยก

## นาที 35–50: ติดตั้งและทำตาม (หน้า 21–25)

เตรียม Python3.11+ และ network สำหรับติดตั้ง Plotly ไว้ล่วงหน้า เวลานี้พอสำหรับสาธิตและลอง run ไม่ใช่แก้บัญชี/connector ทุกคนจนเสร็จ

**21 ชุดแจก:** อธิบายความต่างระหว่าง skill instructions, deterministic Python กับ integrations “skillไม่ได้แถมbrowserconnectorหรือบัญชีของผม ทุกคนใช้บัญชีตัวเอง”

**22 Python:** ใช้คำสั่งจาก INSTALL ตาม OS ไม่ต้อง activate venv บน Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -m pip install -r skills/gold-oi-tactical-dashboard/requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m pip check
```

บน macOS/Linux เปลี่ยนเป็น `python3 -m venv .venv` และ `.venv/bin/python -X utf8` ไม่ปิด certificate validation เพื่อแก้ติดตั้ง

**23 Skill:** เลือกแอปของผู้เรียน รัน installer เพียงตัวเดียวและใช้ project scope ชี้โฟลเดอร์ที่มีอยู่จริง:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/install_skill.py --agent codex --project .
```

แทน `codex` ด้วย `claude` หรือ `antigravity` ได้ Codex/Antigravity ใช้ `.agents/skills` ส่วน Claude Code ใช้ `.claude/skills` บอกให้เห็นชัดว่า Claude เว็บไม่ได้อ่านไฟล์เครื่องได้อัตโนมัติ

**24 CSV:** รัน DEMO smoke test ตาม QUICKSTART ให้ผู้เรียนเห็นไฟล์ที่จะต้องเตรียมจริง จากนั้นแสดง PROMPTS และ source_context แยกหน้าที่ validation, scoring, agent analysis และ rendering โค้ดไม่แต่ง narrative ให้เอง ถ้าขาด data ต้องหยุด ไม่หยิบ DEMO มาตอบ live

**25 Live เสริม:** สาธิต preflight เท่านั้นถ้าเครื่องผู้เรียนยังไม่พร้อม ถ้าพร้อมจึงอ่าน currenttabsตามขอบเขต ไม่เปลี่ยน chart/indicators และต้องอนุญาต Sheet ชัดเจน รักษา old/formulas แล้ว readback การรัน Python ผ่านไม่แปลว่า integration ทั้งสามค่ายผ่าน

## นาที 50–60: แบบฝึกและถามตอบ (หน้า 26–28)

**26 แบบฝึก:** ให้เวลาคิดก่อนเปิดเฉลย A: price+2%, OI−4%, Volumeสูงกว่าbaseline สอดคล้อง covering แต่ยังไม่พิสูจน์ squeeze B: CallOI+500 รู้เพียงยอด Call ค้างเพิ่ม ไม่รู้ buyer/writer intent ถ้าตอบว่า “ซื้อทอง” ให้ถามว่าข้อมูลบรรทัดไหนพิสูจน์การตัดสินใจนั้น

**27 Checklist:** ให้คนเรียนตรวจตัวอย่างรายงานหนึ่งครั้งตาม checklist หากวันที่หรือ basis ไม่ตรงให้หยุดก่อนสรุป ไม่ใช่อ่าน biasแล้วค่อยหาเหตุผลเข้าข้าง

**28 ส่งต่อ:** เปิด GitHub, ชี้ INSTALL/PROMPTS/OI guide/Canva ลิงก์ สรุปสิทธิ์ MITโค้ดกับCCBYเนื้อหา ให้เครดิตArmrileyและระบุการแก้ไข ส่วนproviderdata/Canvaassetsมีสิทธิ์แยก จากนั้นให้ผู้เรียนพูดกลับหนึ่งประโยคว่า “รู้อะไร และยังไม่รู้อะไรจากOI”
